A soldier's way through ccore

From the first day in the regiment to the next rank, these are the commands that carry each step.

  1. Enlists

    /alistar-se opens the form in a pop-up and checks the ROBLOX account for ALTs. Staff can use /enlistuser instead.

  2. Gets called up

    /deployment posts the game code and pings the regiment; /dmdeployment sends it by DM.

  3. Fights, on the record

    /audit-add takes each player's kills, deaths and assists after the battle, straight from the game's output. Every run counts one battle.

  4. The record goes out

    /audit-push publishes the batch to GitHub and, if you want, to the regiment's spreadsheet.

  5. Moves up

    /promocoes shows who has the battles for the next rank. The promotion is still command's call.

Enlistment & Verification

  • /enlistuser Enlists a user with automatic ROBLOX verification
    • Requires: Permission role configured
    • Parameters: user, ROBLOX username
    • Function: Anti-ALT verification + role assignment + nickname + log
  • /alistar-se Self-enlistment with a pop-up form
    • Specific channel required
    • Function: Complete form + automatic ROBLOX verification
    • Doesn't use DMs: people with closed DMs can enlist too

Messages & Communications

  • /deployment Sends deployment message
    • Requires: Permission role configured
    • Parameter: game code
    • Function: Embed with roles ping + access buttons
  • /dmdeployment Sends DM to role/user (with code)
    • Requires: Permission role configured
    • Parameters: role/user, code, message
    • Limit: 500 members per execution
    • If Discord signals a rate limit or too many sends fail in a row, it stops and shows how many went out
  • /dmreminder Sends DM to role/user (without code)
    • Requires: Permission role configured
    • Parameters: role/user, message
    • Limit: 500 members per execution
    • If Discord signals a rate limit or too many sends fail in a row, it stops and shows how many went out

Spreadsheet & Information

  • /checkspreadsheetinfo Queries regimental spreadsheet information
    • Parameter: username in spreadsheet
    • Function: Searches data in spreadsheet Roster tab

Audit System

  • /audit-add Records the audit of a battle
    • Requires: Staff role
    • Function: paste the game's output, check a preview and queue it; each run counts +1 battle
    • Format: name k d a n, where n is the line break the game writes. One player per line or all on one line both work: ana 12 3 5 n bia 4 1 0 n
  • /audit-push Publishes the queue
    • Requires: Staff role
    • Function: adds up the totals and publishes them to GitHub; an error keeps the queue, and publishing again never counts twice
  • /audit-check Looks up the audit
    • Requires: Staff role
    • Function: paged roster, or one player's sheet with K/D
  • /audit-edit Fixes, renames or removes a player
    • Requires: Staff role
    • Function: a pre-filled window with a before/after summary
  • /audit-setranks Sets ranks by hand
    • Requires: Staff role
    • Function: search, gather up to 10 players and set their ranks at once
  • /audit-import Imports the current roster from the spreadsheet
    • Requires: Staff role
    • Function: seeds name, rank and battles; never touches kills, deaths or assists
  • /audit-logs Shows who changed the audit and what they did
    • Requires: Staff role
    • Function: paged history, newest first
  • /promocoes Shows who is eligible for promotion
    • Requires: Staff role
    • Function: applies the regiment's promotion ladder to the audit, for everyone or one player

Repost System

  • /messages Checks message storage status
    • Function: System statistics and progress
  • /repost Reposts random stored message
    • Requires: Minimum of stored messages
    • Cooldown: 2 hours after manual use

Utilities

  • /ping Tests bot latency
    • Function: Returns response time in ms
  • /logs Shows the bot's latest log lines
    • Requires: Staff role
    • Optional parameters: amount, level, text filter, private
  • /dashboardlink Makes a one-time login code for the dashboard
    • Requires: a dashboard level
    • Function: only you see the reply

Administration Commands

  • -osinfo Shows system, process, language and Discord connection info
    • Requires: Staff role
    • Prefix command, not a slash command
  • vsfdliliane Special restricted command
    • Requires: Specific user ID
    • Function: Custom responses

Configuration

The bot uses the config.jsonc file for configurations of:

  • Channel and role IDs
  • Spreadsheet URLs and links
  • Command permissions
  • Custom messages
  • Blocked terms list and automatic blacklist response

Note: the bot now uses the MessageContent intent to read message text and detect blocked terms. This intent also needs to be enabled in the Discord application panel.

Requirements

  • Rust, edition 2024
  • poise + serenity, tokio, axum
  • Proper configuration in config.jsonc
  • Bot permissions in the Discord server
